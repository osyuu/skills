# comment-budget — 註解量守門

註解是**唯一沒有任何自動化在看的產物**：編譯器不管、測試不管、review 通常只看邏輯。所以它是最容易單向膨脹的地方——尤其當寫的人是 AI：模型傾向用註解證明自己想過，而人類讀到的是雜訊，久了乾脆整片跳過。**註解一旦被跳過，那些真正重要的約束也一起被跳過了。**

這個 skill 裝一道 warn-only 的 pre-commit，把量攤在 commit 當下。

## 判準（這比腳本值錢，裝之前先對齊）

> **註解只寫 code 說不出口的事。**

留下：約束（「這裡必須排在 X 之後，否則 Y」）、外部系統的反直覺行為（「這個 API 的 seek 是相對位移」）、給未來的指令（「不要改回 X，除非先量過 Y」）。

三類不寫：

| 類別 | 例子 | 去處 |
|---|---|---|
| a. 重述字面 | `// 把 count 加一` | 刪 |
| b. 變更史 | 「原本是…後來改成…」 | git log |
| c. **驗證過程** | 「兩位 reviewer 各自抓到」「已注入故障反向驗證」 | commit message |

b 和 c 證明的是**作者很認真**，不是系統怎麼運作。讀者要的是後者。c 尤其沒價值——b 至少可能解釋現況為何長這樣。

**最容易踩的地方**：當 code 本身沒什麼好解釋的（純值型別、單純的 view），空間就會被 b 和 c 填滿。實測過一個六欄位的 struct 拿到 64% 註解佔比，而同一次交付裡真正複雜的 coordinator 只有 27%。**越簡單的 code 能負擔的註解越少；沒東西可解釋時，正確答案是不寫。**

## 三個訊號（都 warn-only）

| 訊號 | 預設 | 為什麼 |
|---|---|---|
| 單一註解區塊 | ≥ 10 行 | 超過這個長度通常已經不是「說明一件事」 |
| 單檔新增註解佔比 | > 40% | 抓離群，不抓常態（成熟 codebase 常在 20–25%） |
| 敘事／過程字眼 | 見腳本 | 這兩類可以字面偵測，不必判斷語意 |

佔比檢查有下限（預設註解 ≥ 15 行才計），否則小改動加三行註解就 100%。

字眼清單刻意**不含**「踩過」「實測」——那兩個詞後面常接的是給未來的指令或量到的事實，是有價值的那種。

## 流程

**1. 裝**（idempotent，可重跑）：
```
sh <skill-dir>/scripts/install.sh
```
複製 checker、seed `hooks/comment-budget.conf`（僅當不存在）、marker-guarded 接進 `hooks/pre-commit`、設 `core.hooksPath hooks`。

**2. 先量基準再決定門檻**——這步不要跳過。拿最近 20–30 個 commit 跑一次，看開火率：

```sh
git log --format=%h -25 -- '*.<ext>' | while read c; do
  git diff-tree --no-commit-id --name-only -r "$c" | while read f; do
    git diff "$c~1" "$c" -- "$f" | grep '^+' | grep -v '^+++' | awk -v F="$f" '
      { l=substr($0,2); sub(/^[ \t]+/,"",l)
        if (l ~ /^\/\//) { c2++; run++; if (run>mx) mx=run } else { run=0; if (l!="") k++ } }
      END { t=c2+k; if (t>=20) printf "%-50s %2d%%  max %d\n", F, c2*100/t, mx }'
  done
done
```

**對七成 commit 開火 = 噪音，會被無視；完全不開火 = 等於沒裝。** 目標是只有離群值會亮。既有 codebase 若普遍超標，兩種可能都成立（門檻太緊／習慣真的普遍），這時傾向維持門檻、當一次性清債——arch-guard 剛裝上時也抓出九個既有違規，清完之後長期是 0。

**3. 把判準寫進 CLAUDE.md**。這步才是真正會改變下一次怎麼寫的東西：hook 只在 commit 當下抱怨，CLAUDE.md 每個 session 都載入。上面「判準」那節壓成三四行即可，不要照抄整段——寫一段長註解去講「不要寫長註解」是很糟的示範。

## 已知限制（別對它有錯誤期待）

- **只看本次新增的行**。既有的長註解不追溯，所以裝上去不會一次噴出整個 repo。
- **只看行註解**（`//`、`#`、`--`）。區塊註解 `/* */`、docstring 不計。
- **量得出長度，量不出價值**。一段解釋框架未文件化行為的 15 行註解會被標記，而它可能完全正確——警告是要你確認，不是判它有罪。
- **會誤報「引用壞例子」**。字眼偵測分不出「在寫變更史」和「在舉例說明不要寫變更史」——
  實測 checker 自己就被自己標記兩次，因為它的檔頭引用了那些被禁的字眼。這是刻意不修的：
  要分辨得做語意判斷，而那正是這支腳本明確不做的事。看到警告時人自己判斷比較快。
- **管轄範圍看副檔名**，預設涵蓋 `//` `#` `--` 三類，所以 shell 腳本也在內（包含 checker
  自己）。markdown、JSON、YAML 不在內。要排除特定檔案就從 conf 的副檔名清單拿掉。
